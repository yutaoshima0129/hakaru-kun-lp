# 見る君（プロトタイプ / 第2段階）

飲食店向けAIサイネージの試作品です。ポスターを表示しながら USB カメラで「何人が前を通り、何人が何秒見たか」を計測し、管理画面で効果を確認できます。

- **2つのモード**：環境変数が無ければ **デモモード**（アカウント不要・データはブラウザ内の IndexedDB）、Supabase の設定があれば **クラウドモード**（ログイン・複数端末・スマートフォンからの遠隔操作）
- **映像は保存・送信しない**：顔の検出と向きの推定はパソコンの中（ブラウザ内の MediaPipe）で行い、残すのは1分ごとの人数と秒数だけです

## 起動

```bash
cd miru-kun
npm install      # MediaPipe の WASM が public/mediapipe にコピーされます
npm run dev      # http://localhost:3000
```

| 画面 | URL | 用途 |
|---|---|---|
| トップ | `/` | 入口 |
| サイネージ画面 | `/player` | 店頭モニターに全画面表示。`D` で計測状況、`F` で全画面 |
| ダッシュボード | `/admin` | 通行人数・注視人数・注視率・平均注視時間、時間帯別、ポスター別 |
| 週次レポート | `/admin/report` | 先週との比較、ポスター別ランキング、AIによる改善提案、印刷／PDF保存 |
| ポスター | `/admin/posters` | アップロード、表示時間、表示/非表示、並び替え、表示する曜日・時間帯（即時反映） |
| ポスターを作る | `/admin/posters/new` | メニュー情報からポスターを3案作成（AI またはテンプレート） |
| 端末と設定 | `/admin/devices` | 端末の登録（クラウド）、「見た」の判定基準、計測中の表示 |

> カメラは `localhost` か `https://` でしか使えません。
> デモモードでは、管理画面とサイネージ画面を **同じパソコン・同じブラウザ** で開いてください。別の場所から操作したい場合はクラウドモードを使います。
> カメラの選択は、サイネージ画面で `D` キーを押した計測状況パネルから行います（端末のブラウザに保存）。

## モード

| | デモモード | クラウドモード |
|---|---|---|
| 切り替え | 環境変数なし（既定） | `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_ANON_KEY` を設定 |
| データの保存先 | ブラウザ内（IndexedDB / localStorage） | Supabase（Postgres + Storage） |
| ログイン | なし | メールアドレスとパスワード |
| 店舗・端末 | このパソコン1台だけ | 複数店舗・複数端末 |

## クラウドモードのセットアップ

1. [Supabase](https://supabase.com/) でプロジェクトを作成する
2. SQL Editor で `supabase/migrations/` の SQL を番号順（`0001_init.sql` → `0002_storage.sql` → `0003_poster_schedule.sql`）に実行する
3. `.env.local.example` を `.env.local` にコピーし、Project Settings → API の値を入れる
   ```
   NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=...
   ```
4. 開発サーバーを再起動する（環境変数はビルド時に埋め込まれます）
5. `/admin` で新規登録 →「最初の店舗を登録」

SQL（テーブル・RLS・関数）のテストは `bash supabase/tests/run.sh` で実行できます。

### 端末のペアリング

1. 管理画面の「端末と設定」→「端末を追加」で名前を付けると、ペアリングコード（`XXXX-XXXX`）が表示されます
2. 店頭のパソコンで `/player` を開き、コードを入力して「登録」
3. 登録後はログイン不要で、ポスターの取得と計測データの送信を自動で行います（送信は60秒ごと。通信できないときは端末内に貯めて再送します）
4. コードの期限切れや端末の入れ替えは「ペアリングをやり直す」で再発行。端末側は `D` キー →「登録を解除」でも外せます

## AI 機能（ポスター作成・週次レポートの分析）

Claude（`claude-opus-5-5`）が、ポスターの文言と配色、週次レポートの改善提案を作ります。

- `.env.local` に `ANTHROPIC_API_KEY` を設定すると有効になります（キーはサーバー側だけで使い、ブラウザには渡しません）
- クラウドモードではログイン中のオーナーだけが使えます。デモモードで使う場合は `MIRU_ALLOW_DEMO_AI=1` も設定してください（公開サーバーでは設定しない）
- ポスターの絵は画像生成 AI で描かず、AI が考えた文言と配色をテンプレートに流し込んで描画します（日本語の文字が崩れないように）
- 安全上の理由で断られた場合は、サーバー側で別のモデルに自動で切り替えます（`fallbacks: "default"`）
- 週次レポートで送るのは集計した数字だけです（映像や個人の情報は含みません）
- キーが無くても、ポスターは「テンプレートで3案つくる」で作れます

## 表示スケジュール

ポスターごとに表示する曜日と時間帯を設定できます（例：ランチは平日 11:00〜14:00、ハッピーアワーは 17:00〜19:00）。終了が開始より早い時刻なら日付またぎ（22:00〜02:00 など）として扱います。判定は店頭のパソコンの時計で行い、30秒ごとに切り替わります。

## 試し方

1. 管理画面 →「ポスター」→「サンプルを追加」
2. 「サイネージ画面を開く」→ カメラを許可 → `D` キーで計測状況を表示
3. カメラの前で画面を見る（緑枠＝見ている／赤枠＝見ていない）
4. 10秒ごと（クラウドは60秒ごと）に保存され、ダッシュボードに反映されます
5. 見た目だけ確認したい場合は（デモモードのみ）ダッシュボードの「デモデータを入れて見た目を確認」

## 判定の仕組み

1. MediaPipe Face Landmarker で顔を検出（最大5人, 約10fps）
2. 顔の変換行列から「顔の正面方向」と「顔→カメラ方向」のずれ角（左右・上下）を計算
3. ずれが許容角度（初期値 左右±20°・上下±15°）以内なら「見ている」
4. 0.3秒以上映った人を **通行**、0.5秒以上見続けた人を **注視** として1回だけ数える
5. 見ている間の時間を **注視時間** として、その時表示中のポスターに加算
6. 1人の通行と注視は、その人を通行として数えた時に表示中だったポスターにまとめて計上（途中で切り替わっても注視率が100%を超えない）

ロジックは `lib/attention.ts`（ブラウザ非依存）にあり、`npm test` でテストできます。

## カメラ設置のコツ

- モニター上部の中央に、少し下向きで取り付ける
- 逆光（入口のガラス越しの外光）を避ける
- 有効距離の目安は **0.5〜2m**。これより遠い人は検出されにくくなります（第1段階で遠距離向けの検出モデルを検討）
- 設置後、サイネージ画面で `D` →「いまの顔の向きを『画面を見ている』として補正」を押すと、カメラとモニター中央の位置ずれを補正できます

## 既知の制約

- デモモードのデータは端末のブラウザ内のみ。ブラウザのデータ削除で消えます
- 同じ人が一度フレームアウトして戻ると、別の人として数えます（日をまたいだ識別は意図的にしていません）
- 眼球の視線ではなく **顔の向き** で判定しています
- 週次レポートのメール配信は未対応（画面からの印刷／PDF保存のみ）
